# 로컬 클로드 코드에게 시키기 — OPAC 주소 규칙 자동으로 채우기

이 저장소의 원격 세션에서는 **국내 도서관 사이트에 접속할 수 없습니다.** 그리고 예전에
GitHub Actions 러너에서 돌렸을 때도 30묶음 가운데 18묶음이 접속조차 되지 않았습니다.
**국내 회선에서 돌아야 뜻이 있는 일**이라, 로컬에서 도는 클로드 코드에게 넘깁니다.

아래 「넘길 말」을 그대로 붙여 넣으시면 됩니다.

---

## 왜 이번에는 될 만한가

2026-09-09 의 자동 조사는 **0/30** 이었습니다. 판정 로직은 멀쩡했고(가짜 OPAC 일곱 종류를
통과합니다) 걸린 것은 둘이었습니다.

| 그때 막힌 것 | 지금 |
|---|---|
| **검색어가 경로에 들어가는 OPAC** 을 못 찾음. 자바스크립트가 주소를 만들어 HTML 에 그 형태가 없습니다 | `opac-browse.py` 가 **브라우저 주소창에서 읽습니다** |
| 국내 공공도서관 상당수가 **해외 IP 차단** | 로컬(국내)에서 돌리면 사라집니다 |

앞의 것이 큰 쪽입니다. 실제로 규칙을 얻은 열세 묶음 가운데 **넷이 경로형**이었고
(노원·부천·서초·안산), 전부 사람이 주소창을 보고 알려 준 것입니다.

`scripts/test-opac-browse.py` 가 그것을 가짜 OPAC 으로 고정합니다. **같은 사이트를
폼 읽기로는 못 찾고 브라우저로는 찾는 것**을 한 파일 안에서 나란히 확인합니다.

## 넘길 말 (이 아래를 그대로 붙여 넣으세요)

> `where-is-my-book` 저장소에서 도서관 OPAC 검색 주소 규칙을 채워 주세요.
> 먼저 `CLAUDE.md` 의 「OPAC 주소 규칙을 추측해서 넣지 마세요」와
> `docs/도서관-주소-규칙-채우기.md` 를 읽으세요.
>
> **준비**
>
> ```bash
> pip install playwright && playwright install chromium
> ./scripts/test-opac-browse.py        # 먼저 이게 통과하는지 보세요
> ./scripts/opac-discover.py --probe   # 검증용 소장 데이터 (우리 API 를 씁니다)
> ```
>
> 이 도구는 검색 규칙과 함께 **상세 페이지 규칙까지 시도합니다.** 검색 결과에서 책을 눌러
> 들어간 주소에 ISBN 이 그대로 있으면 `ISBN_DETAIL` 로 넣고, 내부 키를 쓰면 버립니다.
>
> **1. 가장 값싼 것부터: 이미 규칙이 있는 기관에서 빠진 55곳**
>
> ```bash
> ./scripts/opac-browse.py --gaps
> ```
>
> 고양 19 · 안산 16 · 서초 10 · 은평 7 · 순천 2 · 의정부 1 곳입니다. 묶음키가 홈페이지의
> 첫 경로 조각까지 보는 탓에 한 시스템이 둘로 갈렸고, 하필 사람이 많이 가는 큰 도서관만
> 빠졌습니다. `--gaps` 는 그 기관의 기존 규칙 주소를 열어 **빠진 도서관 이름이 검색 화면에
> 실제로 보이는지** 봅니다. 전부 보이면 「넓혀도 됩니다」와 함께 `묶음키*` 줄을 찍어 줍니다.
>
> **안산은 조심하세요.** 지금 규칙이 `lib.ansan.go.kr/smalllib/...` 라 작은도서관 전용
> 검색입니다. 시립도서관이 안 보이면 넓히지 말고 시립용 주소를 따로 찾아야 합니다.
>
> **2. 아직 규칙이 없는 묶음**
>
> ```bash
> ./scripts/opac-browse.py --limit 30      # 큰 묶음부터. 중단해도 이어서 됩니다
> ./scripts/opac-browse.py --emit > findings.txt
> ./scripts/opac-discover.py --import-file findings.txt \
>     >> backend/src/main/resources/opac/templates.csv
> ```
>
> **3. 확인하고 커밋**
>
> ```bash
> ./scripts/opac-discover.py --gaps        # 새로 갈린 묶음이 생겼는지
> cd backend && ./gradlew test             # 자리표 없는 줄이 있으면 서버가 안 뜹니다
> git status                               # templates.csv 가 보이는지 (예전에 .gitignore 가 삼켰습니다)
> ```
>
> **절대 완화하면 안 되는 것들입니다. 통과율을 올리려고 손대지 마세요.**
>
> - **음성 대조를 빼지 마세요.** 검색어와 무관하게 늘 목록을 뿌리는 OPAC 이 전부 「성공」이
>   되어, 어느 책을 눌러도 남의 책이 뜨는 규칙이 들어갑니다.
> - **확인은 쿠키 없는 새 창에서 합니다.** 주소창에는 검색어가 남는데 새 창에서 열면
>   무시하는 OPAC 이 있습니다(제주·구미·용산). 같은 창에서 확인하면 통과하지만 사용자에게는
>   죽은 링크가 나갑니다.
> - **양성에 쓰는 ISBN 은 그 도서관이 실제로 소장한 책이어야 합니다.** 아니면 0건이 나왔을
>   때 규칙이 틀린 것인지 그 책이 없는 것인지 구별할 수 없습니다.
> - **주소를 짐작해서 넣지 마세요.** 틀린 규칙은 HTTP 200 을 주면서 결과만 0건이 되어
>   「소장한다더니 그 책이 없네」로 보입니다. 깨진 링크와 달리 눈에 띄지 않습니다.
> - **`_csrf` 같은 세션 토큰이 붙는 주소는 규칙이 될 수 없습니다.** 오늘은 되고 내일은
>   안 됩니다. 상세 페이지의 내부 키(`book_key`, `regNo`, `bookkey`)도 마찬가지입니다.
> - **같은 호스트에 한 번에 하나씩, 3초 간격을 지키세요**(`--host-delay`). robots.txt 가
>   막은 경로는 건드리지 않습니다. 남의 서버입니다.
> - **정보나루를 직접 부르지 마세요.** 검증용 소장 데이터는 `--probe` 가 우리 API 를 통해
>   받습니다. 인증키는 서버에만 있습니다.
> - 찾은 규칙은 반드시 `--import-file` 을 지나가게 하세요. 자리표·인코딩·다른 기관 도메인을
>   거기서 한 번 더 거릅니다. `templates.csv` 에 손으로 직접 붙이지 마세요.
>
> **막히면 그대로 두세요.** 이 프로젝트는 **누락이 오병합보다 낫다**는 규칙으로 돌아갑니다.
> 규칙이 없는 도서관은 홈페이지로 가고 화면이 그 사실을 밝힙니다. 그것은 정상 동작이지
> 고쳐야 할 실패가 아닙니다.
>
> 커밋 메시지는 저장소의 기존 것들을 보고 맞춰 주세요. 무엇을 확인해서 넣었는지와 몇 곳이
> 늘었는지를 적습니다.

## 이 도구가 만드는 것과 만들지 않는 것

**`ISBN_SEARCH` 와 `ISBN_DETAIL` 만 만듭니다.** 검색 결과에서 책을 눌러 들어간 주소에
ISBN 이 그대로 있으면 상세 규칙까지 얻고, 다른 책의 ISBN 으로 바꿔 열어 확인합니다.
대부분은 도서관 내부 키라(`book_key`, `regNo`, `bookkey`) 자리표를 만들 수 없어 검색
규칙만 남습니다.

**`TITLE_SEARCH` 는 만들지 않습니다.** ISBN 검색이 안 되는 OPAC 은 제목으로 내려가는 대신
그냥 버립니다. 한글 질의어라 인코딩을 함께 맞춰야 하는데, 그것을 자동으로 틀리면 **200 이
오면서 결과만 0건**이 되어 눈에 띄지 않습니다. 그 자리는 사람이 주소창의 한글이
`%C4%DA...`(EUC-KR)인지 `%EC%BD%94...`(UTF-8)인지 보고 넣는 편이 안전합니다.

## 틀리면 어느 쪽으로 틀리나

**버리는 쪽으로 틀립니다.** 세 겹 검증은 전부 「이게 아니면 버린다」라서, 통과하지 못한
규칙은 들어가지 않고 그 도서관은 지금처럼 홈페이지로 갑니다. 화면이 그 사실을 밝히므로
사용자를 속이지 않습니다.

실제로 **맞는 규칙을 버리는 경우가 있습니다.** 검증에 쓰는 「그 도서관이 소장한 책」은
정보나루가 알려 준 것인데, 정보나루의 소장 정보와 그 도서관 OPAC 이 어긋날 수 있습니다
(노원에서 21곳과 14곳으로 갈렸습니다). 그러면 규칙이 맞아도 그 책이 0건이라 버려집니다.
**아쉽지만 이 방향의 실수는 안전합니다.**
