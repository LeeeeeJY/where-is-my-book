# 가정과 검증 상태

이 저장소의 코드가 어디까지 검증되었고 어디부터 추측인지 적어 둡니다.
API 문서를 열어 보지 못한 채 만든 부분이 있으므로, 그것을 확인된 사실처럼
다루지 않기 위해서입니다.

세션의 네트워크 정책이 `data4library.kr`, `nl.go.kr`, `data.go.kr` 을 차단하고 있어
(CONNECT 단계에서 403) 공식 문서와 실제 응답을 확인하지 못했습니다.

---

## 1. 실제로 실행해 검증한 것

| 대상 | 어떻게 |
|---|---|
| DB 스키마 | PostgreSQL 16 에 실제로 적용하고, `short_id` 불변 트리거·ISBN 제약·멱등성 제약·색인 전환의 원자성을 각각 동작시켜 확인 |
| 도서관 선택 화면 | 실제 Chromium 에서 조작. 부분 선택의 `indeterminate`, 상위 자동 체크, URL 반영, 다른 브라우저에서 복원, 좁은 화면 배치까지 15가지 |
| 로직 전반 | 테스트 85개 (백엔드) + 22개 (프론트) |

여기까지는 "돌아간다"고 말해도 됩니다.

---

## 2. 내부적으로만 일관된 것

**테스트를 통과한다는 것이 실제 데이터를 잘 다룬다는 뜻은 아닙니다.**

### golden-pairs.tsv 는 자기 채점입니다

47쌍은 제가 직접 쓴 것입니다. 정밀도 1.000 은 **"코드가 제 판단과 일치한다"** 는 뜻이지
**"실제 도서관 데이터를 잘 처리한다"** 는 뜻이 아닙니다.

실제 서지를 적재하면 제가 생각하지 못한 형태가 반드시 나옵니다. 그때마다 이 파일에 한 줄씩
추가하면서 200건까지 늘리는 것이 원래 계획이고, 그 전까지 이 수치를 품질 근거로 인용하면 안 됩니다.

### 정규화 규칙은 관례에 대한 제 지식에서 나왔습니다

KORMARC 245 구분 기호 처리, 판본 표기 목록, 각색 표기 목록, 저자 역할어 목록은
한국 서지 관례에 대한 일반 지식으로 만든 것이고 **실제 정보나루 레코드를 본 적이 없습니다.**

특히 아래는 실물을 보면 바뀔 가능성이 높습니다.

- 구분 기호가 실제로 ` / `, ` = `, ` : ` 형태로 오는지, 아니면 이미 정제되어 오는지
- 권차 표기의 실제 분포 (지금 다섯 가지 패턴을 다루지만 더 있을 수 있음)
- 판본과 각색 목록에서 빠진 표기

### 규모 추정은 검색 결과 기반입니다

1,604개관, 장서 2억 289만 권은 정보나루 집계값을 검색 결과에서 읽은 것입니다.
복본율 1.3, ISBN 보유율 80% 는 제 가정이고 실측이 아닙니다.

## 3. 순수한 추측 — 확인 전에는 믿으면 안 됩니다

전부 `scripts/probe-apis.sh` 안에만 있습니다.

| 항목 | 지금 값 | 근거 |
|---|---|---|
| `libSrchByBook` 응답의 도서관 태그 | `<lib>` | **추측.** 확인 전까지 개수 세기가 0 이 나올 수 있음 |
| `libSrch` 응답의 코드 태그 | `<libCode>` | 추측 |
| 공공데이터포털 도서관 정보 엔드포인트 | `apis.data.go.kr/B551408/lib-info/getLibInfo` | **지어낸 경로.** 활용신청 화면의 실제 주소로 바꿔야 함 |
| 지역 코드 11 = 서울 | 그대로 사용 | 추측 |
| 정보나루 1일 한도 30,000건 | 계획 전반의 전제 | 검색 결과 |
| 서지정보 API 응답 필드 이름 | 아직 없음 | 파서를 아예 만들지 않음 |

## 왜 그래도 진행할 수 있었는가

**자바 코드에는 외부 API 형식이 하나도 들어 있지 않습니다.** 외부와 닿는 지점이
인터페이스 셋뿐입니다.

```
HoldingsLookup.HoldingsClient   — ISBN 과 지역 코드로 도서관부호 목록을 받음
HttpApiSourceAdapter.Transport  — URI 로 응답 본문을 받음
SourceAdapter                   — 소스 형태의 레코드를 내보냄
```

그래서 응답 구조가 무엇으로 밝혀지든 **구현체 하나만 쓰면 되고 나머지는 바뀌지 않습니다.**
추측이 틀렸을 때 고칠 곳이 좁게 격리되어 있다는 뜻입니다.

## 잘못된 가정이 조용히 통과하지 않게 한 장치

가정이 틀렸을 때 **틀렸다고 드러나도록** 만든 것들입니다.

- `HoldingsLookup` 은 `region` 필요 여부를 확정하지 않고 첫 조회에서 알아냅니다.
  전국과 지역이 모두 빈 결과이면 **확정하지 않고 모른다고 남깁니다.**
- 빈 결과(미소장)와 조회 실패(확인 불가)를 타입에서부터 구분합니다.
  섞이면 실제로 있는 책을 없다고 답해 헛걸음을 만듭니다.
- `probe-apis.sh` 는 판정이 애매하면 "판정 보류"를 내고 원본을 직접 보라고 합니다.
  억지로 결론 내지 않습니다.
- `IndexVerifier` 는 ISBN 이 없는 문서, 검색되지 않는 문서, 저작 번호가 중복된 문서를 잡습니다.
- CSV 헤더 지문이 다르면 적재를 **실패시킵니다.** 컬럼이 밀린 채 들어가면 나중에 발견할 수 없습니다.

## 그래서 지금 상태를 뭐라고 불러야 하나

**뼈대와 규칙은 돌아가고, 실제 데이터로는 검증되지 않았습니다.**

`./scripts/probe-apis.sh` 를 한 번 돌려 `probe-out/REPORT.md` 를 얻으면 3번 항목이
전부 사실로 바뀌고, 그다음 실제 서지를 적재하면서 2번 항목을 하나씩 교정하게 됩니다.
