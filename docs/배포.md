# 배포

**프론트와 API 서버를 반드시 나눠서 올립니다.** 프론트는 정적 자산이라 어디에 올려도 되지만,
API 서버는 그렇지 않습니다. 이유가 아래 첫 절에 있습니다.

---

## API 서버를 서버리스에 올리면 안 됩니다

Vercel Functions, Cloudflare Workers, Lambda 같은 곳에 올리면 **나가는 IP 가 고정되지
않습니다.** 정보나루의 1일 30,000건 한도는 서버 IP 를 등록해야 적용되므로, IP 가 바뀌면
등록 효과를 받지 못하고 **1일 500건**으로 떨어집니다.

문제는 이것이 **오류 없이 조용히** 일어난다는 점입니다. 평소에는 멀쩡하다가 여러 권 확인
두어 번에 한도가 소진되고, 화면에는 "확인 불가"가 쏟아집니다. 코드도 로그도 정상이라
원인을 찾는 데 한참 걸립니다.

**그래서 API 서버는 고정 IP 를 붙일 수 있는 상시 컨테이너나 VM 에 올립니다.**
같은 이유로 GitHub Actions 에서 정보나루를 호출하지 않습니다. 러너의 IP 도 고정되지 않습니다.

---

## 어디에 올릴지 고르기

결정하는 조건은 하나입니다. **나가는 IP 가 고정되는가.**

들어오는 IP 가 아니라 **우리 서버가 정보나루를 부를 때 찍히는 주소**입니다. 이 둘을
혼동하면 "고정 IP 를 준다"는 서비스를 골라 놓고도 등록이 먹지 않습니다.

| 어디 | 월 비용 | 나가는 IP | HTTPS | 비고 |
|---|---|---|---|---|
| 국내 VPS (카페24, 가비아, 네이버클라우드) | 5,000~10,000원 | **확실히 고정** | 직접 설정 | 정보나루와 가깝습니다 |
| Oracle Cloud 프리 티어 | **무료** | **확실히 고정** | 직접 설정 | ARM 인스턴스. Dockerfile 그대로 됩니다 |
| Fly.io | 약 2달러 + 인스턴스 | 전용 IPv4 필요, **확인 요함** | 자동 | 설정이 가장 간단합니다 |
| Render / Railway 유료 | 7달러~ | 플랜에 따라 다름 | 자동 | 플랜 문서를 확인해야 합니다 |
| Vercel, Workers, Lambda | — | **고정 안 됨** | — | **쓰면 안 됩니다** |

**VM 한 대(VPS, Oracle 프리 티어)를 권합니다.** IP 가 하나뿐이라 나가는 주소에 모호함이
없기 때문입니다. 지금 관리하는 위험이 "등록이 조용히 안 먹는 것"이므로, 모호함이 없는
쪽이 맞습니다. 대신 HTTPS 를 직접 붙여야 하는데 아래에 방법을 적어 두었습니다.

---

## 나가는 IP 를 눈으로 확인하세요

**등록하기 전에 반드시 합니다.** 여기서 확인하지 않으면, 한도가 500 건에서 막히는 것을
하루가 지나서야 알게 됩니다.

```bash
# VM 에 접속한 상태에서
curl -s https://api.ipify.org; echo

# Fly.io 라면
fly ssh console -C "curl -s https://api.ipify.org"
```

여기서 나온 주소를 정보나루 마이페이지 > 인증키 관리 > 서버IP 에 등록합니다.
`fly ips list` 가 보여 주는 것은 **들어오는** 주소이므로, 위 명령의 결과와 다르면
위 명령 쪽이 맞습니다.

며칠 뒤 `/api/status` 의 `callsRemaining` 이 500 근처에서 막히는지도 확인하세요.
막힌다면 등록이 먹지 않은 것입니다.

## 1. API 서버

배포 단위는 `backend/Dockerfile` 하나입니다. 아래는 권하는 순서대로입니다.

### VM 한 대에 올릴 때 (VPS, Oracle 프리 티어) — 권장

도커와 Caddy 만 있으면 됩니다. Caddy 가 인증서를 자동으로 받아 주므로 HTTPS 설정이
세 줄로 끝납니다.

```bash
# 1. 이미지를 만들어 띄웁니다
git clone <저장소> && cd where-is-my-books/backend
docker build -t wimb-api .
docker run -d --name wimb-api --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -e D4L_AUTH_KEY=발급받은키 \
  -e WIMB_CORS_ALLOWED_ORIGINS=https://내앱.vercel.app \
  wimb-api

# 2. Caddy 로 HTTPS 를 붙입니다 (/etc/caddy/Caddyfile)
#   api.내도메인.kr {
#       reverse_proxy 127.0.0.1:8080
#   }
sudo systemctl reload caddy
```

`-p 127.0.0.1:8080:8080` 으로 묶는 것이 중요합니다. 이렇게 해야 8080 이 바깥에 그대로
열리지 않고 Caddy 를 거칩니다.

도메인이 없으면 Caddy 대신 그냥 `-p 8080:8080` 으로 열고 `VITE_API_BASE` 를 `http://IP:8080`
으로 둘 수도 있지만, 브라우저가 HTTPS 페이지에서 HTTP 를 부르는 것을 막기 때문에
**Vercel 에 올린 프론트에서는 동작하지 않습니다.** 도메인과 인증서가 필요합니다.

### Fly.io 에 올릴 때

`backend/fly.toml` 이 준비되어 있습니다.

```bash
cd backend
fly launch --no-deploy        # 앱 이름과 지역만 확인하고 넘어갑니다
fly ips allocate-v4           # 전용 IPv4. 월 약 2달러입니다

fly secrets set D4L_AUTH_KEY=발급받은키
fly secrets set WIMB_CORS_ALLOWED_ORIGINS=https://내앱.vercel.app
fly deploy
```

**등록할 주소는 `fly ips list` 가 아니라 아래 명령의 결과입니다.**

```bash
fly ssh console -C "curl -s https://api.ipify.org"
```

`fly ips list` 는 **들어오는** 주소를 보여 줍니다. 전용 IPv4 가 나가는 쪽에도 쓰이는지는
계정과 설정에 따라 다를 수 있으므로, 위 명령으로 실제 나가는 주소를 확인한 뒤 그것을
등록하세요. 두 값이 같으면 그대로 쓰면 됩니다.

### 그 밖의 곳에 올릴 때

고정 IP 만 붙일 수 있으면 어디든 됩니다. `backend/Dockerfile` 을 그대로 쓰고 아래 환경
변수만 넣어 주세요.

| 환경 변수 | 필수 | 설명 |
|---|---|---|
| `D4L_AUTH_KEY` | **예** | 정보나루 인증키. 비어 있으면 서버가 뜨지 않습니다 |
| `WIMB_CORS_ALLOWED_ORIGINS` | 예 | 프론트 도메인. 쉼표로 여러 개 |
| `WIMB_DATA4LIBRARY_DAILY_CALL_BUDGET` | 아니요 | 기본 25000. 30,000 한도에 여유를 둔 값입니다 |
| `WIMB_DATA4LIBRARY_MIN_REQUEST_INTERVAL_MS` | 아니요 | 기본 120. 상대 서버에 대한 예의입니다 |

키가 비어 있으면 서버가 그 사실을 말하고 뜨지 않습니다. 키 없이 조용히 떠서 모든 조회가
실패하는 것보다 낫기 때문입니다.

### 살아 있는지 보기

```bash
curl https://api.내도메인.kr/api/status
# {"librariesLoaded":0,"callsUsedToday":0,"callsRemaining":25000}
```

`callsRemaining` 이 하루 동안 어떻게 줄어드는지 보면 **IP 등록이 실제로 먹었는지** 알 수
있습니다. 500건 언저리에서 막힌다면 등록이 안 된 것입니다.

첫 `/api/libraries` 호출은 시도 17곳을 훑기 때문에 몇 초 걸립니다. 그동안 화면에는
"도서관 목록을 받는 중입니다"가 보입니다.

## 2. 프론트엔드

Vite 프로젝트라 설정이 거의 없습니다.

1. Vercel 에서 이 저장소를 가져옵니다.
2. **Root Directory 를 `frontend` 로 지정합니다.** 저장소 최상위가 아닙니다.
3. 환경 변수에 `VITE_API_BASE` 를 API 서버 주소로 넣습니다. (예: `https://api.내도메인.kr`)
4. 나머지는 자동으로 잡힙니다. (Framework: Vite, Build: `npm run build`, Output: `dist`)

`vercel.json` 에 SPA 재작성 규칙이 들어 있어 나중에 라우터를 붙여도 새로고침이 깨지지
않습니다.

CLI 로 하려면 `frontend` 안에서 다음과 같이 합니다.

```bash
npx vercel        # 미리보기
npx vercel --prod # 운영
```

**`VITE_API_BASE` 를 넣지 않으면** 프론트가 `http://localhost:8080` 을 찾습니다. 배포본에서는
연결에 실패하고, 화면은 샘플 도서관 24곳으로 내려앉으면서 **그것이 샘플이라는 사실을
밝힙니다.** 조용히 샘플을 보여 주지는 않으니 잘못된 결과를 믿게 되지는 않습니다.

## 3. 로컬에서 먼저 보기

```bash
# API 서버
cd backend
set -a; . ../.env; set +a
./gradlew bootRun          # http://localhost:8080

# 화면
cd frontend
npm install
npm run dev                # http://localhost:5173
```

API 서버 없이 화면만 띄워도 도서관 선택은 동작합니다. 다만 샘플이라는 표시가 뜨고 책
검색은 되지 않습니다.

## 올린 뒤에 확인할 것

- **나가는 IP 가 등록한 주소와 같은가** (위 "나가는 IP 를 눈으로 확인하세요")
- `/api/status` 의 `callsRemaining` 이 25,000 에서 시작하는가
- 하루를 넘겨도 500 근처에서 막히지 않는가 (**IP 등록이 먹었는지 판별하는 지점입니다**)
- 도서관 목록이 샘플 24곳이 아니라 실제 목록인가
- 여러 권 확인에서 책 정보가 먼저 그려지고 소장이 나중에 채워지는가
- 소장 정보의 조회 시각과 "출처: 도서관 정보나루" 가 화면에 보이는가
