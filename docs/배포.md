# 배포

프론트엔드는 정적 자산이라 어디에 올려도 됩니다. API 서버는 별개이고 아직 없습니다.

## 지금 상태로 올리면 보이는 것

도서관 선택 화면은 완전히 동작합니다. 고르고, 새로고침해도 유지되고, 주소를 공유하면
다른 기기에서 그대로 복원됩니다.

**책 검색은 아직 안 됩니다.** 서지 데이터가 없기 때문이고, 화면에도 그렇게 적혀 있습니다.
도서관 목록도 24곳짜리 샘플입니다. 실제 목록은 공공데이터포털 인증키를 받아야 들어옵니다.

## Vercel

Vite 프로젝트라 별도 설정이 거의 없습니다.

1. Vercel 에서 이 저장소를 가져옵니다.
2. **Root Directory 를 `frontend` 로 지정합니다.** 저장소 최상위가 아닙니다.
3. 나머지는 자동으로 잡힙니다. (Framework: Vite, Build: `npm run build`, Output: `dist`)

`vercel.json` 에 SPA 재작성 규칙이 들어 있어 나중에 라우터를 붙여도 새로고침이 깨지지
않습니다.

CLI 로 하려면 `frontend` 안에서 다음과 같이 합니다.

```bash
npx vercel        # 미리보기
npx vercel --prod # 운영
```

## 로컬에서 먼저 보기

```bash
cd frontend
npm install
npm run dev       # http://localhost:5173
```

## 나중에 API 서버가 붙으면

프론트는 정적, API 는 Fly.io 컨테이너로 나눕니다. **정보나루에 등록할 고정 IP 가
API 서버 쪽에 붙어야 하기 때문입니다.** 소장 조회가 사용자 요청 처리 중에 일어나므로,
등록되지 않은 IP 에서 나가면 조용히 1일 500건 한도가 적용됩니다.

Vercel 의 서버리스 함수로 API 를 만들면 나가는 IP 가 고정되지 않아 이 문제가 생깁니다.
**프론트만 Vercel 에 두세요.**
