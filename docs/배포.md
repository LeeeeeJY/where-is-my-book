# 배포

> **지금 실제로 이렇게 올라가 있습니다.** 아래는 고르는 과정까지 함께 적어 둔 문서라
> 선택지가 여럿 나오지만, 정해진 것은 하나입니다.
>
> | | 어디 |
> |---|---|
> | API 서버 | Google Compute Engine 무료 등급 `e2-micro` (`us-central1`) + Caddy(HTTPS) |
> | 프론트 | Vercel |
> | 정보나루에 등록한 IP | VM 의 고정 공인 IP |
>
> 서버를 **처음 만드는 절차**는 [`구글-서버-만들기.md`](구글-서버-만들기.md) 에 화면 단위로
> 적어 두었습니다. 이 문서는 **왜 그렇게 정했는지**와 다른 선택지를 남겨 둔 것입니다.

**프론트와 API 서버를 반드시 나눠서 올립니다.** 프론트는 정적 자산이라 어디에 올려도 되지만,
API 서버는 그렇지 않습니다. 이유가 아래 첫 절에 있습니다.

---

## API 서버를 서버리스에 올리면 안 됩니다

Vercel Functions, Cloudflare Workers, Lambda 같은 곳에 올리면 **나가는 IP 가 고정되지
않습니다.** 정보나루의 1일 30,000건 한도는 서버 IP 를 등록해야 적용되므로, IP 가 바뀌면
등록 효과를 받지 못하고 **1일 500건**으로 떨어집니다.

문제는 이것이 **오류 없이 조용히** 일어난다는 점입니다. 평소에는 멀쩡하다가 여러 권 확인
두어 번에 한도가 소진되고, 화면에는 "확인 불가"가 쏟아집니다. 코드도 로그도 정상이라
원인을 찾는 데 한참 걸립니다.

**그래서 API 서버는 고정 IP 를 붙일 수 있는 상시 컨테이너나 VM 에 올립니다.**
같은 이유로 GitHub Actions 에서 정보나루를 호출하지 않습니다. 러너의 IP 도 고정되지 않습니다.

---

## 어디에 올릴지 고르기

결정하는 조건은 하나입니다. **나가는 IP 가 고정되는가.**

들어오는 IP 가 아니라 **우리 서버가 정보나루를 부를 때 찍히는 주소**입니다. 이 둘을
혼동하면 "고정 IP 를 준다"는 서비스를 골라 놓고도 등록이 먹지 않습니다.

아래는 2026년 9월에 확인한 내용입니다. 무료 등급의 조건은 자주 바뀌므로 고르기 전에
각 서비스 문서를 한 번 더 보세요.

| 어디 | 월 비용 | 나가는 IP | HTTPS | 비고 |
|---|---|---|---|---|
| **Google Compute Engine 무료 등급** | **무료** | **확실히 고정** | 직접 설정 | e2-micro. **미국 리전만** 되고 공인 IP 는 무료입니다 |
| 국내 VPS (카페24, 가비아, 네이버클라우드) | 5,000~10,000원 | **확실히 고정** | 직접 설정 | 재고 걱정이 없습니다 |
| Oracle Cloud 프리 티어 | 무료 | **확실히 고정** | 직접 설정 | **한국 리전은 재고 부족이 잦습니다.** 춘천은 ARM 자체가 안 됩니다 |
| Fly.io | 약 2달러 + 인스턴스 | 전용 IPv4 필요, **확인 요함** | 자동 | 설정이 가장 간단합니다 |
| Render / Railway 유료 | 7달러~ | 플랜에 따라 다름 | 자동 | 플랜 문서를 확인해야 합니다 |
| Vercel, Cloud Run, App Engine, Workers, Lambda | — | **고정 안 됨** | — | **쓰면 안 됩니다** |

**Cloud Run 과 App Engine 도 안 됩니다.** 구글이라고 다른 것이 아니라 서버리스라서 같은
문제입니다. 고정하려면 Cloud NAT 을 붙여야 하는데 그것만으로 월 30달러가 넘어, VPS 보다
비쌉니다.

**VM 한 대를 권합니다.** IP 가 하나뿐이라 나가는 주소에 모호함이 없기 때문입니다. 지금
관리하는 위험이 "등록이 조용히 안 먹는 것"이므로, 모호함이 없는 쪽이 맞습니다.
그중에서는 **실제로 받을 수 있다는 점에서 Google 무료 등급이 무난합니다.** Oracle 은 사양이
훨씬 좋지만 한국 리전에서 인스턴스를 못 받는 경우가 잦습니다.

### 서버가 미국에 있어도 느려지지 않습니다

호출 간격이 왕복 시간을 가리기 때문입니다. `ThrottledHttpTransport` 는 요청을 120ms 간격으로
내보내되 **응답을 기다리는 동안 잠금을 잡지 않으므로**, 왕복 시간은 서로 겹칩니다.

```
30권 확인 = 약 60회 호출
  한국 서버: 60 × 120ms + 왕복 50ms  ≈ 7.3초
  미국 서버: 60 × 120ms + 왕복 250ms ≈ 7.5초
```

**전체 차이가 0.2초입니다.** 그러니 "정보나루와 가깝다"를 이유로 국내를 고를 필요는 없습니다.
다만 `pace()` 안에서 요청까지 기다리도록 코드를 바꾸면 이 계산이 무너지므로,
**호출을 잠금 안으로 옮기지 마세요.**

## 나가는 IP 를 눈으로 확인하세요

**등록하기 전에 반드시 합니다.** 여기서 확인하지 않으면, 한도가 500 건에서 막히는 것을
하루가 지나서야 알게 됩니다.

```bash
# VM 에 접속한 상태에서
curl -s https://api.ipify.org; echo

# Fly.io 라면
fly ssh console -C "curl -s https://api.ipify.org"
```

여기서 나온 주소를 정보나루 마이페이지 > 인증키 관리 > 서버IP 에 등록합니다.
`fly ips list` 가 보여 주는 것은 **들어오는** 주소이므로, 위 명령의 결과와 다르면
위 명령 쪽이 맞습니다.

며칠 뒤 `/api/status` 의 `callsRemaining` 이 500 근처에서 막히는지도 확인하세요.
막힌다면 등록이 먹지 않은 것입니다.

## 1. API 서버

배포 단위는 `backend/Dockerfile` 하나입니다. 아래는 권하는 순서대로입니다.

### Google 무료 등급 e2-micro 에 올릴 때

#### 무료로 유지하는 조건 (2026-09 확인)

아래를 벗어나면 그 순간부터 과금됩니다. 무료 등급 조건은 자주 바뀌므로 만들기 전에
공식 문서를 한 번 더 보세요.

| 항목 | 무료 범위 |
|---|---|
| 인스턴스 | `e2-micro` **한 대**. 두 대째부터 과금 |
| 리전 | **`us-west1`, `us-central1`, `us-east1` 뿐** |
| 디스크 | **표준 영구 디스크** 30GB 까지. SSD 를 고르면 과금 |
| 공인 IP | 인스턴스에 **붙어 있는 동안** 무료 |
| 아웃바운드 | 북미발 월 1GB (중국·호주 제외) |

**돈이 새는 곳은 대개 여기입니다.**

- **리전을 잘못 고르는 것.** 서울에 만들면 그냥 과금됩니다. 무료 세 곳 중에서 고르세요.
- **인스턴스를 지우거나 멈추고 고정 IP 를 남겨 두는 것.** 붙어 있지 않은 고정 IP 는
  **쓰고 있을 때보다 더 비싼 요율로** 과금됩니다. 인스턴스를 정리할 때 IP 도 함께
  해제하세요.
- 디스크를 SSD(`pd-balanced`, `pd-ssd`)로 고르는 것. 기본값이 아닐 수 있으니 확인하세요.

**결제 알림을 걸어 두세요.** 예산을 1달러로 잡고 알림을 켜 두면 새는 순간 바로 알 수
있습니다. 결제 > 예산 및 알림에서 만듭니다.

콘솔을 처음 쓰신다면 [`구글-서버-만들기.md`](구글-서버-만들기.md) 에 계정 만들기부터
화면 연결까지 단계별로 적어 두었습니다.

#### 올리는 순서

**메모리가 1GB 뿐이라 순서를 지켜야 합니다.** 그냥 하면 두 군데에서 막힙니다.

#### 1. 인스턴스를 만듭니다

- 머신 종류 `e2-micro`, 리전은 **`us-west1` / `us-central1` / `us-east1` 중 하나**여야
  무료입니다. 다른 리전은 과금됩니다.
- 부팅 디스크는 Ubuntu 24.04 LTS, 30GB 표준 영구 디스크(무료 한도)로 둡니다.
- 방화벽에서 **HTTP(80)와 HTTPS(443)를 허용**합니다. Caddy 가 인증서를 받으려면 필요합니다.

#### 2. 스왑을 먼저 잡습니다 — 건너뛰면 빌드가 죽습니다

`docker build` 안에서 Gradle 이 도는데, **Gradle 컴파일만으로 1GB 를 넘깁니다.**
스왑 없이 하면 빌드가 중간에 죽고 원인이 잘 보이지 않습니다.

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # 재부팅 뒤에도 유지
free -h                                                       # Swap 2.0Gi 확인
```

#### 3. 도커와 Caddy 를 깝니다

```bash
sudo apt-get update
sudo apt-get install -y docker.io caddy git
sudo usermod -aG docker $USER && newgrp docker
```

#### 4. 나가는 IP 를 확인해 정보나루에 등록합니다

```bash
curl -s https://api.ipify.org; echo
```

**이 주소**를 정보나루 마이페이지 > 인증키 관리 > 서버IP 에 넣습니다.
GCE 는 기본이 임시 IP 이므로, VPC 네트워크 > IP 주소에서 **고정(static)으로 승격**해 두세요.
그러지 않으면 인스턴스를 재시작할 때 주소가 바뀌어 등록이 무효가 됩니다.

#### 5. 띄웁니다

```bash
git clone https://github.com/LeeeeeJY/where-is-my-book.git
cd where-is-my-book/backend
docker build -t wimb-api .

docker run -d --name wimb-api --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v wimb-data:/data \
  -e D4L_AUTH_KEY=발급받은키 \
  -e WIMB_CORS_ALLOWED_ORIGINS=https://where-is-my-book.vercel.app \
  wimb-api

curl localhost:8080/api/status
```

**`-v wimb-data:/data` 를 빠뜨리지 마세요.** 소장 캐시 스냅샷이 여기 쌓입니다. 없으면
컨테이너를 바꿀 때마다 캐시가 함께 사라져서, 배포 직후마다 같은 책을 다시 묻는 호출이
그대로 나갑니다. 호스트 디렉터리 대신 이름 있는 볼륨을 쓰는 것은 컨테이너가 루트가 아닌
사용자로 돌기 때문입니다. 호스트 디렉터리를 붙이면 소유권이 맞지 않아 쓰기가 막힙니다.

힙은 이미지에서 메모리의 50% 로 잡아 두었습니다. 1GB 기계에서 75% 로 두면 JVM 자체가 쓰는
몫이 더해져 한도를 넘고 **OOM 킬러가 컨테이너를 조용히 죽입니다.** 바꾸려면
`-e JAVA_OPTS="-XX:MaxRAMPercentage=40"` 처럼 넘기면 됩니다.

#### 6. Caddy 로 HTTPS 를 붙입니다

`/etc/caddy/Caddyfile` 에 세 줄이면 됩니다.

```
api.내도메인.kr {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
```

도메인의 A 레코드를 이 서버의 고정 IP 로 먼저 돌려 놓아야 인증서를 받습니다.

### 그 밖의 VM 에 올릴 때 (VPS, Oracle)

도커와 Caddy 만 있으면 됩니다. Caddy 가 인증서를 자동으로 받아 주므로 HTTPS 설정이
세 줄로 끝납니다.

```bash
# 1. 이미지를 만들어 띄웁니다
git clone <저장소> && cd where-is-my-books/backend
docker build -t wimb-api .
docker run -d --name wimb-api --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v wimb-data:/data \
  -e D4L_AUTH_KEY=발급받은키 \
  -e WIMB_CORS_ALLOWED_ORIGINS=https://where-is-my-book.vercel.app \
  wimb-api

# 2. Caddy 로 HTTPS 를 붙입니다 (/etc/caddy/Caddyfile)
#   api.내도메인.kr {
#       reverse_proxy 127.0.0.1:8080
#   }
sudo systemctl reload caddy
```

`-p 127.0.0.1:8080:8080` 으로 묶는 것이 중요합니다. 이렇게 해야 8080 이 바깥에 그대로
열리지 않고 Caddy 를 거칩니다.

**Google 무료 등급(e2-micro)은 메모리가 1GB 라 빠듯합니다.** Dockerfile 이
`-XX:MaxRAMPercentage=75` 를 쓰므로 그대로도 뜨지만, 여유가 없으면 스왑을 조금 잡아 두세요.
방화벽에서 80 과 443 을 열어야 Caddy 가 인증서를 받습니다.

도메인이 없으면 Caddy 대신 그냥 `-p 8080:8080` 으로 열고 `VITE_API_BASE` 를 `http://IP:8080`
으로 둘 수도 있지만, 브라우저가 HTTPS 페이지에서 HTTP 를 부르는 것을 막기 때문에
**Vercel 에 올린 프론트에서는 동작하지 않습니다.** 도메인과 인증서가 필요합니다.

### Fly.io 에 올릴 때

`backend/fly.toml` 이 준비되어 있습니다.

```bash
cd backend
fly launch --no-deploy        # 앱 이름과 지역만 확인하고 넘어갑니다
fly ips allocate-v4           # 전용 IPv4. 월 약 2달러입니다

fly secrets set D4L_AUTH_KEY=발급받은키
fly secrets set WIMB_CORS_ALLOWED_ORIGINS=https://where-is-my-book.vercel.app
fly deploy
```

**등록할 주소는 `fly ips list` 가 아니라 아래 명령의 결과입니다.**

```bash
fly ssh console -C "curl -s https://api.ipify.org"
```

`fly ips list` 는 **들어오는** 주소를 보여 줍니다. 전용 IPv4 가 나가는 쪽에도 쓰이는지는
계정과 설정에 따라 다를 수 있으므로, 위 명령으로 실제 나가는 주소를 확인한 뒤 그것을
등록하세요. 두 값이 같으면 그대로 쓰면 됩니다.

### 그 밖의 곳에 올릴 때

고정 IP 만 붙일 수 있으면 어디든 됩니다. `backend/Dockerfile` 을 그대로 쓰고 아래 환경
변수만 넣어 주세요.

| 환경 변수 | 필수 | 설명 |
|---|---|---|
| `D4L_AUTH_KEY` | **예** | 정보나루 인증키. 비어 있으면 서버가 뜨지 않습니다 |
| `WIMB_CORS_ALLOWED_ORIGINS` | 예 | 프론트 도메인. 쉼표로 여러 개 |
| `WIMB_DATA4LIBRARY_DAILY_CALL_BUDGET` | 아니요 | 기본 25000. 30,000 한도에 여유를 둔 값입니다 |
| `WIMB_DATA4LIBRARY_MIN_REQUEST_INTERVAL_MS` | 아니요 | 기본 120. 상대 서버에 대한 예의입니다 |
| `WIMB_HOLDINGS_CACHE_PATH` | 아니요 | 소장 캐시 스냅샷 위치. 이미지가 `/data/holding-cache.tsv.gz` 로 박아 둡니다 |
| `WIMB_HOLDINGS_SAVE_INTERVAL_MS` | 아니요 | 기본 60000. 스냅샷을 얼마나 자주 저장할지 |
| `WIMB_RATE_LIMIT_BEHIND_PROXY` | 아니요 | 기본 true. **Caddy 같은 프록시 없이 포트를 직접 열었으면 false 로 두세요** |
| `WIMB_RATE_LIMIT_PER_MINUTE` | 아니요 | 기본 400. 주소 하나가 1분에 쓸 수 있는 무게 |
| `WIMB_RATE_LIMIT_BURST` | 아니요 | 기본 800. 한꺼번에 몰아 쓸 수 있는 무게 |
| `WIMB_RATE_LIMIT_PER_DAY` | 아니요 | 기본 5000. 주소 하나가 하루에 쓸 수 있는 무게 |
| `WIMB_RATE_LIMIT_ENABLED` | 아니요 | 기본 true. **끈 채로 두지 마세요** |

키가 비어 있으면 서버가 그 사실을 말하고 뜨지 않습니다. 키 없이 조용히 떠서 모든 조회가
실패하는 것보다 낫기 때문입니다.

#### 주소별 호출 제한에서 한 가지만 조심하세요

**`WIMB_RATE_LIMIT_BEHIND_PROXY` 가 실제 배치와 어긋나면 한쪽으로 크게 틀립니다.**
지금 배포는 Caddy 뒤이므로 기본값 `true` 가 맞습니다.

- `true` 인데 프록시가 없으면, 아무나 `X-Forwarded-For` 헤더를 지어내 한도를 빠져나갑니다.
  막으려고 만든 것이 아무것도 막지 못합니다.
- `false` 인데 프록시 뒤에 있으면, **모든 이용자가 프록시 주소 하나로 뭉뚱그려져 서로의
  한도를 나눠 씁니다.** 사람이 몰리는 시간에 멀쩡한 요청이 무더기로 막히고, 화면에는
  「확인 불가」가 쏟아집니다. 정보나루 장애와 증상이 같아서 원인을 엉뚱한 데서 찾게 됩니다.

`X-Forwarded-For` 는 프록시를 지날 때마다 **뒤에 덧붙으므로 마지막 값**을 씁니다. 흔히 하는
대로 첫 값을 쓰면 클라이언트가 지어낸 값을 믿게 됩니다.

한도의 단위는 요청 수가 아니라 **무게**입니다. 요청마다 정보나루를 부르는 횟수가 크게
다르기 때문인데, `/api/status` 한 번은 한 번도 부르지 않고 `/api/check/resolve` 한 번은
줄마다 두세 번씩 불러 백 번을 넘길 수 있습니다. 같은 한 번으로 세면 **가장 비싼 요청이
가장 싸게 통과합니다.** 무게표는 `RateLimitInterceptor.costOf` 에 있습니다.

### 살아 있는지 보기

```bash
curl https://api.내도메인.kr/api/status
# {"librariesLoaded":0,"callsUsedToday":0,"callsRemaining":25000,
#  "rateLimitedClients":0,"holdingCacheEntries":0}
```

**`holdingCacheEntries` 는 소장 캐시가 살아 있는지 말해 줍니다.** 재배포한 지 얼마 지나지
않았는데 이 값이 0이면 스냅샷을 잃은 것입니다. 볼륨(`-v wimb-data:/data`)이 붙어 있는지
먼저 보세요. 이 값이 자라는 동안에는 같은 책을 다시 묻는 호출이 나가지 않습니다.

`callsRemaining` 이 하루 동안 어떻게 줄어드는지 보면 **IP 등록이 실제로 먹었는지** 알 수
있습니다. 500건 언저리에서 막힌다면 등록이 안 된 것입니다.

**`rateLimitedClients` 는 지금 몇 개의 주소를 세고 있는지입니다.** 호출이 갑자기 줄었을 때
이 숫자가 없으면 사람이 안 오는 것인지 우리가 막고 있는 것인지 구별할 수 없어 추측하게
됩니다. **이 값이 1 인데 이용자가 여럿이면 `WIMB_RATE_LIMIT_BEHIND_PROXY` 를 의심하세요.**
모두가 프록시 주소 하나로 뭉뚱그려지고 있다는 뜻입니다. 주소 자체는 내보내지 않습니다.

첫 `/api/libraries` 호출은 시도 17곳을 훑기 때문에 몇 초 걸립니다. 그동안 화면에는
"도서관 목록을 받는 중입니다"가 보입니다.

### 배포 뒤 한 번에 훑기

정적 파일은 조용히 404 가 되어도 화면이 멀쩡하므로 **눈으로는 알 수 없습니다.** 한 번
훑어 두세요.

```bash
SITE=https://where-is-my-book.vercel.app
API=https://api.내도메인.kr

for u in "$SITE/privacy" "$SITE/privacy.html" "$SITE/robots.txt" "$SITE/sitemap.xml" \
         "$SITE/og.png" "$API/robots.txt"; do
  printf '%-58s %s\n' "$u" "$(curl -sS -o /dev/null -w '%{http_code}' "$u")"
done

curl -s "$API/api/version"   # 새 커밋 해시가 나와야 합니다
curl -s "$API/api/status"    # rateLimitedClients 가 보여야 합니다
```

전부 `200` 이어야 합니다. 어긋났을 때 어디를 봐야 하는지는 아래와 같습니다.

| 증상 | 뜻 |
|---|---|
| `/api/status` 에 `rateLimitedClients` 가 없음 | 예전 이미지가 돌고 있습니다. `/api/version` 의 해시를 보세요 |
| `/privacy` 는 200 인데 앱 첫 화면이 뜸 | `vercel.json` 의 재작성 규칙이 안 먹었습니다. `/privacy.html` 은 열리는지 함께 보면 갈립니다 |
| `$API/robots.txt` 가 404 | 크롤러가 막는 규칙이 없는 것으로 보고 `/api/go/…` 를 훑습니다 |
| `/og.png` 가 404 | 공유 미리보기가 빈 카드로 나갑니다. 공유해 보기 전에는 눈에 띄지 않습니다 |

**검색엔진 등록은 이 확인을 마친 뒤에 하세요.** 등록 절차에서 `robots.txt` 와
`sitemap.xml` 을 제출하는데, 배포 전이면 검사기가 404 를 받습니다.

## 2. 프론트엔드

Vite 프로젝트라 설정이 거의 없습니다.

1. Vercel 에서 이 저장소를 가져옵니다.
2. **Root Directory 를 `frontend` 로 지정합니다.** 저장소 최상위가 아닙니다.
3. 환경 변수에 `VITE_API_BASE` 를 API 서버 주소로 넣습니다. (예: `https://api.내도메인.kr`)
4. 나머지는 자동으로 잡힙니다. (Framework: Vite, Build: `npm run build`, Output: `dist`)

`vercel.json` 에 SPA 재작성 규칙이 들어 있어 나중에 라우터를 붙여도 새로고침이 깨지지
않습니다. **규칙의 순서가 중요합니다.** `/privacy` 를 `/privacy.html` 로 보내는 줄이
`/(.*)` 앞에 있어야 합니다. 뒤로 가면 개인정보처리방침이 앱 첫 화면으로 넘어가 버립니다.
그리고 **`vercel.json` 에 주석 삼아 모르는 키를 넣지 마세요.** 스키마 검사에 걸려 배포가
통째로 실패합니다. 설명은 이 문서에 적습니다.

**도메인을 바꾸면 `frontend/index.html` 도 함께 고쳐야 합니다.** 공유 미리보기용 태그
네 줄(`canonical`, `og:url`, `og:image`, `twitter:image`)에 주소가 절대 경로로 들어
있습니다. 상대 경로로는 미리보기를 만드는 쪽에서 그림을 찾지 못하기 때문인데, 그래서
도메인이 바뀌면 조용히 예전 주소를 가리키게 됩니다. 미리보기 그림 자체는
`frontend/tools/og-image.html` 이 원본이고 `node tools/make-og-image.mjs` 로 다시 만듭니다.

CLI 로 하려면 `frontend` 안에서 다음과 같이 합니다.

```bash
npx vercel        # 미리보기
npx vercel --prod # 운영
```

**환경 변수를 넣은 뒤에는 반드시 다시 배포해야 합니다.** Vite 의 `VITE_*` 값은 실행할 때가
아니라 **빌드할 때 코드에 박힙니다.** Vercel 대시보드에서 값만 넣고 재배포하지 않으면
이미 빌드된 번들에는 예전 주소가 그대로 남아 있어, 아무리 기다려도 화면이 바뀌지 않습니다.
값을 넣은 뒤 Deployments 에서 Redeploy 를 누르세요.

**`VITE_API_BASE` 를 넣지 않으면** 프론트가 `http://localhost:8080` 을 찾습니다. 배포본에서는
연결에 실패하고, 화면은 샘플 도서관 24곳으로 내려앉으면서 **그것이 샘플이라는 사실을
밝힙니다.** 조용히 샘플을 보여 주지는 않으니 잘못된 결과를 믿게 되지는 않습니다.

## 올린 뒤에 확인할 것

- **나가는 IP 가 등록한 주소와 같은가** (위 "나가는 IP 를 눈으로 확인하세요")
- **재배포한 뒤에도 `/api/status` 의 `holdingCacheEntries` 가 0으로 돌아가지 않는가**
  (0이면 볼륨이 안 붙은 것입니다)
- `/api/status` 의 `callsRemaining` 이 25,000 에서 시작하는가
- 하루를 넘겨도 500 근처에서 막히지 않는가 (**IP 등록이 먹었는지 판별하는 지점입니다**)
- 도서관 목록이 샘플 24곳이 아니라 실제 목록인가
- 여러 권 확인에서 책 정보가 먼저 그려지고 소장이 나중에 채워지는가
- 소장 정보의 조회 시각과 "출처: 도서관 정보나루" 가 화면에 보이는가
