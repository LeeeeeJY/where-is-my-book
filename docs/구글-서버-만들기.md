# Google Compute Engine 에 API 서버 올리기

Compute Engine 을 처음 쓰는 사람을 위한 안내입니다. 콘솔 화면은 수시로 바뀌므로 메뉴 이름이
조금 다를 수 있지만, 골라야 하는 값과 순서는 그대로입니다.

전체 배포 구성과 "왜 서버리스가 아니라 VM 인가"는 [`배포.md`](배포.md) 를 보세요.

---

## 0. 시작 전에 — 여기서 제일 많이 헷갈립니다

Google Cloud 에는 **성격이 다른 두 가지 무료**가 있습니다.

| | 무료 체험 (Free Trial) | Always Free |
|---|---|---|
| 내용 | 90일 동안 300달러 크레딧 | 매달 정해진 양이 계속 무료 |
| 기간 | 90일 | **기간 없음** |
| 우리가 쓸 것 | 아닙니다 | **이것입니다** (e2-micro 1대) |

**Always Free 에는 기간 제한이 없습니다.** 소량으로만 쓰면 계속 무료입니다. 이 프로젝트의
API 서버는 e2-micro 한 대로 충분하므로 여기에 들어갑니다.

한 가지만 주의하면 됩니다. **체험 기간이 끝나면 계정이 체험 상태로 남아 있는 동안 워크로드가
정지됩니다.** Always Free 를 계속 쓰려면 **유료 계정으로 업그레이드**해야 합니다.

이름이 무섭지만 **업그레이드가 곧 과금은 아닙니다.** 업그레이드는 계정을 체험 상태에서
정식 상태로 바꾸는 것이고, 요금은 Always Free 범위를 **넘겼을 때만** 붙습니다. 범위 안에
머무르면 계속 0원입니다. 자동으로 과금이 시작되는 일도 없습니다.

**그러니 계정을 만든 뒤 일찍 업그레이드해 두세요.** 90일 뒤에 서버가 조용히 멈추는 것을
막는 방법입니다. 남은 크레딧도 그대로 쓸 수 있습니다. 그리고 아래 2단계의 예산 알림을
같이 걸어 두면, 혹시 범위를 넘겨도 바로 알 수 있습니다.

### 무료로 유지되는 범위

| 항목 | 무료 범위 |
|---|---|
| 인스턴스 | `e2-micro` **한 대** |
| 리전 | **`us-west1`(오리건), `us-central1`(아이오와), `us-east1`(사우스캐롤라이나) 뿐** |
| 디스크 | **표준 영구 디스크** 30GB 까지 |
| 공인 IP | 인스턴스에 **붙어 있는 동안** 무료 |
| 아웃바운드 | 북미발 월 1GB |

돈이 새는 곳은 대개 넷입니다.

1. **리전을 서울로 고르는 것**
2. **디스크를 SSD(균형 잡힌 영구 디스크 포함)로 고르는 것**
3. **스냅샷 일정을 켠 채로 두는 것.** 새 콘솔이 `default-schedule-1` 을 기본으로 붙이는데,
   스냅샷 저장 용량은 Always Free 에 포함되지 않습니다.
4. **인스턴스를 지우고 고정 IP 만 남겨 두는 것.** 쓰고 있을 때보다 비싼 요율이 붙습니다.

3번은 금액이 작지만 「정상이면 0원」이라는 기준을 무너뜨립니다. 나중에 예산 알림이 울렸을 때
진짜 문제인지 스냅샷인지 구분할 수 없게 되므로 꺼 두는 편이 낫습니다. 이 서버는 코드가 전부
GitHub 에 있고 컨테이너만 다시 띄우면 복구되므로 스냅샷이 필요하지 않습니다.

## 1. 계정과 프로젝트

1. [console.cloud.google.com](https://console.cloud.google.com) 에 구글 계정으로 들어갑니다.
2. 결제 수단을 등록합니다. **무료 등급도 카드 등록이 필요합니다.**
3. 위쪽 프로젝트 선택기에서 **새 프로젝트**를 만듭니다. 이름은 `where-is-my-book` 정도로 둡니다.

---

## 2. 예산 알림을 먼저 걸어 둡니다

서버를 만들기 **전에** 합니다. 새는 순간 바로 알 수 있어야 하기 때문입니다.

**결제 > 예산 및 알림 > 예산 만들기**

- 금액: **1달러**
- 알림 임계값: 50%, 90%, 100%
- 이메일 알림 켜기

1달러로 잡는 이유는, 정상이라면 0원이어야 하므로 **1달러가 나오는 것 자체가 신호**이기
때문입니다.

## 3. VM 인스턴스 만들기

**Compute Engine > VM 인스턴스**로 갑니다. 처음이면 API 사용 설정 버튼이 뜨는데 누르고
1~2분 기다립니다.

**인스턴스 만들기**를 누릅니다. **표시한 것은 반드시 맞춰야 무료입니다.**

> 새 콘솔은 왼쪽에 단계 목록(**머신 구성 / OS 및 스토리지 / 데이터 보호 / 네트워킹 / 보안 /
> 고급**)이 있고 항목이 그 안에 나뉘어 있습니다. 예전 화면은 한 페이지에 다 있습니다.
> 아래에 어느 단계에 있는지 함께 적었습니다.

**머신 구성**

| 항목 | 값 |
|---|---|
| 이름 | `wimb-api` |
| 리전 | **`us-west1`** (또는 `us-central1`, `us-east1`) |
| 영역 | 아무거나 (`us-west1-a`) |
| 머신 계열 | 범용 |
| 시리즈 | **E2** |
| 머신 유형 | **`e2-micro`** (2 vCPU, 1GB 메모리) |

**OS 및 스토리지** — 부팅 디스크의 **변경**을 누릅니다.

| 항목 | 값 |
|---|---|
| 운영체제 | Ubuntu |
| 버전 | **Ubuntu 24.04 LTS (x86/64, amd64)** |
| 부팅 디스크 유형 | **표준 영구 디스크** |
| 크기 | 30GB |

**부팅 디스크 유형을 꼭 확인하세요.** 기본값이 `균형 잡힌 영구 디스크(pd-balanced)` 인
경우가 많은데, 그대로 두면 **무료 범위를 벗어나 과금됩니다.**

**버전도 26.04 가 아니라 24.04 LTS 로 직접 고르세요.** 기본값이 26.04 인데, 그쪽은 sudo 가
막혀서 손이 한 번 더 갑니다(5-1절).

**네트워킹** — 왼쪽 단계 목록에서 **네트워킹**을 누르면 위쪽에 **방화벽** 항목이 있고
체크박스가 셋 있습니다. 앞의 둘만 켭니다.

| 항목 | 값 |
|---|---|
| HTTP 트래픽 허용 | **체크** |
| HTTPS 트래픽 허용 | **체크** |
| 부하 분산기 상태 확인 허용 | 그대로 둡니다 |

80번은 뒤에서 Caddy 가 인증서를 받을 때, 443번은 브라우저가 API 를 부를 때 씁니다.
정작 서버가 듣는 8080번은 바깥에 열지 않습니다.

> 체크하는 것을 잊고 만들었더라도 인스턴스를 다시 만들 필요는 없습니다. **VM 인스턴스
> 목록에서 이름을 누르고 「수정」**으로 들어가면 같은 체크박스가 있습니다. 「네트워크 태그」에
> `http-server` 와 `https-server` 를 직접 넣어도 결과가 같습니다.

**만들기**를 누릅니다. 1분쯤 걸립니다.

### 만든 뒤에 확인하기

VM 인스턴스 목록에서 이름을 누르면 세부정보가 나옵니다. 아래로 내려 셋을 확인합니다.

| 확인할 곳 | 이어야 하는 값 | 아니면 |
|---|---|---|
| 머신 유형 | `e2-micro` | 무료 범위를 벗어납니다 |
| 부팅 디스크 > 유형 | **`표준 영구 디스크`** | 과금됩니다 |
| 부팅 디스크 > 스냅샷 일정 | **비어 있음** | 과금됩니다 |
| 네트워크 태그 | `http-server`, `https-server` | 방화벽 체크를 빠뜨린 것입니다 |

스냅샷 일정에 `default-schedule-1` 같은 값이 있으면, **Compute Engine > 스토리지 > 디스크**에서
그 디스크를 누르고 **수정 > 스냅샷 일정**을 `없음` 으로 바꾼 뒤 저장합니다.

디스크 유형이 `균형 잡힌 영구 디스크` 로 되어 있으면, 정지 후 디스크를 바꾸는 것보다
인스턴스를 지우고 다시 만드는 편이 빠릅니다. 네트워크 태그는 「수정」에서 채울 수 있습니다.

이름이 `instance-20260906-134041` 처럼 기본값이어도 상관없습니다. 표시용일 뿐입니다.

## 4. IP 를 고정으로 바꿉니다

기본값은 임시 IP 라 **인스턴스를 재시작하면 주소가 바뀝니다.** 그러면 정보나루에 등록해 둔
주소가 무효가 되어 하루 한도가 500건으로 떨어집니다.

**VPC 네트워크 > IP 주소**로 갑니다. 위쪽 검색창에 「IP 주소」를 쳐도 나옵니다. 왼쪽 위 햄버거 메뉴에 있고, 위쪽 검색창에 「IP 주소」를
쳐도 나옵니다.

1. **외부 IP 주소** 탭에 방금 만든 `wimb-api` 행이 있고, **유형** 열이 `임시`로 되어 있습니다.
2. 그 행의 유형을 **`고정`으로 바꿉니다.** 유형 열이 드롭다운이면 거기서 고르고, 아니면
   행 오른쪽 끝의 **⋮ > 고정 주소로 예약**을 누릅니다.
3. 이름을 물으면 `wimb-api-ip` 로 두고 **예약**을 누릅니다.

**이미 붙어 있는 주소를 고정으로 바꾸는 것이므로 주소값은 바뀌지 않습니다.** 정보나루에
등록할 주소를 이 시점에 적어 두어도 됩니다.

> 인스턴스 「수정」의 네트워크 인터페이스에서 바꾸는 길도 있지만, **예약해 둔 고정 주소가
> 하나도 없으면 드롭다운에 고를 것이 나타나지 않아** 막히는 경우가 있습니다. 위 경로가
> 확실합니다.

> 위쪽의 「외부 IP 주소 예약」 버튼으로 새로 만들 수도 있지만 권하지 않습니다. 리전을 직접
> 골라야 하는데 VM 과 다른 리전을 고르면 붙일 수가 없고, **인스턴스에 붙지 않은 IP 는 쓰고
> 있을 때보다 비싼 요율로 과금됩니다.** 이미 있는 행을 바꾸는 쪽이 안전합니다.

> 인스턴스에 붙어 있는 동안은 무료입니다. 나중에 인스턴스를 지울 때 **이 IP 도 같은 화면에서
> 함께 삭제**하세요. 남겨 두면 그때부터 과금됩니다.

## 5. 접속하기

키를 따로 만들 필요가 없어 가장 간단합니다.

## 5-1. Ubuntu 26.04 를 골랐다면 sudo 가 막힙니다

**24.04 를 골랐으면 이 절은 건너뛰세요.** 콘솔 기본값이 26.04 라서 그대로 만들기 쉬운데,
그 경우 `sudo` 가 이렇게 거부합니다.

```
sudo: I'm sorry <사용자>. I'm afraid I can't do that
```

`id` 에는 `google-sudoers` 가 멀쩡히 보이는데도 거부합니다. Ubuntu 25.10 부터 기본 sudo 가
`sudo-rs` 로 바뀌었는데, **`sudo-rs 0.2.13` 은 sudoers 규칙에서 그룹을 이름으로 적으면
해석하지 못합니다.** GCE 가 넣어 두는 규칙이 하필 이름으로 되어 있습니다.

```
%google-sudoers ALL=(ALL:ALL) NOPASSWD:ALL     ← 이름이라 읽지 못합니다
```

만든 직후 잠깐 되다가 안 되는 경우가 있는데, 자동 업데이트가 sudo 를 교체하는 시점 때문입니다.

**고치려면 시작 스크립트를 씁니다. root 로 돌기 때문에 sudo 가 필요 없습니다.**

**VM 인스턴스 > 이름 클릭 > 수정 > 메타데이터 > 항목 추가**에서 키를 `startup-script` 로 두고
값에 아래를 넣은 뒤 저장하고, 위쪽의 **재설정**을 누릅니다.

```bash
#!/bin/bash
echo '%#1001 ALL=(ALL:ALL) NOPASSWD:ALL' > /etc/sudoers.d/99-sudo-rs-gid
chmod 0440 /etc/sudoers.d/99-sudo-rs-gid
apt-get update
apt-get install -y docker.io caddy git
usermod -aG docker 계정이름
```

`1001` 은 `id` 결과에 나온 `google-sudoers` 의 그룹 번호입니다. 다를 수 있으니 확인하고 넣으세요.
이름 대신 번호로 같은 권한을 다시 적어 주는 것입니다. 7단계의 설치까지 함께 넣었으므로
재설정 한 번으로 끝나고, 다시 접속해서 `sudo -v` 와 `docker ps` 가 조용히 통과하면 된 것입니다.

sudo 가 살아난 뒤에 아예 예전 sudo 로 되돌리고 싶으면 아래 두 줄이면 됩니다.

```bash
sudo apt-get install -y sudo.ws
sudo update-alternatives --set sudo /usr/bin/sudo.ws
```

## 6. 스왑을 먼저 잡습니다

**이 단계를 건너뛰면 다음 단계에서 빌드가 죽습니다.** 뒤에서 `docker build` 가 Gradle 을
돌리는데, 컴파일만으로 메모리 1GB 를 넘깁니다.

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

마지막 줄의 결과에 `Swap` 이 `2.0Gi` 로 나오면 됩니다.

## 8. 나가는 IP 를 확인해 정보나루에 등록합니다

```bash
curl -s https://api.ipify.org; echo
```

**여기 나온 주소**를 정보나루 마이페이지 > 인증키 관리 > 서버IP 에 넣습니다.
4단계에서 고정으로 바꾼 주소와 같아야 정상입니다.

이 등록이 1일 한도를 500건에서 30,000건으로 올립니다. 등록하지 않으면 **오류 없이 조용히**
500건이 적용되어, 여러 권 확인 두어 번에 한도가 소진되고 화면에 "확인 불가"가 쏟아집니다.

## 9. 서버 띄우기

```bash
git clone https://github.com/LeeeeeJY/where-is-my-book.git
cd where-is-my-book/backend
docker build -t wimb-api .
```

빌드는 3~5분쯤 걸립니다. 6단계의 스왑이 없으면 여기서 죽습니다.

```bash
docker run -d --name wimb-api --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -e D4L_AUTH_KEY=발급받은키 \
  -e WIMB_CORS_ALLOWED_ORIGINS=https://where-is-my-book.vercel.app \
  wimb-api

curl localhost:8080/api/status
```

이렇게 나오면 성공입니다.

```json
{"librariesLoaded":0,"callsUsedToday":0,"callsRemaining":25000}
```

`-p 127.0.0.1:8080:8080` 은 8080 을 바깥에 열지 않고 서버 안에서만 열어 둔다는 뜻입니다.
바깥과는 다음 단계의 Caddy 가 이야기합니다.

`--restart unless-stopped` 덕분에 서버를 재부팅해도 컨테이너가 알아서 다시 뜹니다.

## 10. HTTPS 붙이기 — 도메인이 필요합니다

**Vercel 에 올린 프론트가 HTTPS 라, 브라우저가 HTTP 로 된 API 호출을 막습니다.**
그래서 도메인과 인증서가 있어야 화면이 실제로 동작합니다.

도메인이 있으면 A 레코드를 4단계의 고정 IP 로 돌린 뒤,

```bash
sudo nano /etc/caddy/Caddyfile
```

내용을 이렇게 바꿉니다.

```
api.내도메인.kr {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
curl https://api.내도메인.kr/api/status
```

Caddy 가 인증서를 자동으로 받아 옵니다. DNS 가 퍼지는 데 몇 분 걸릴 수 있습니다.

---

## 11. 프론트와 연결하기

Vercel 프로젝트 > Settings > Environment Variables 에 넣습니다.

```
VITE_API_BASE = https://api.내도메인.kr
```

**넣은 뒤 반드시 Deployments 에서 Redeploy 를 누르세요.** Vite 의 `VITE_*` 는 실행할 때가
아니라 **빌드할 때 코드에 박히기 때문에**, 값만 넣고 재배포하지 않으면 이미 만들어진
번들에 예전 주소가 그대로 남습니다. 아무리 기다려도 화면이 바뀌지 않습니다.

---

## 잘 되었는지 확인하기

- `curl https://api.내도메인.kr/api/status` 가 `callsRemaining: 25000` 을 돌려주는가
- 사이트를 열었을 때 **"API 서버에 연결하지 못했습니다"** 경고가 사라졌는가
- 도서관 목록이 샘플 24곳이 아니라 실제 목록인가
- 며칠 뒤 `callsRemaining` 이 500 근처에서 막히지 않는가
  (막힌다면 8단계의 IP 등록이 먹지 않은 것입니다)

## 막혔을 때

| 증상 | 원인과 조치 |
|---|---|
| `sudo: I'm sorry ... I can't do that` | Ubuntu 26.04 의 sudo-rs 버그입니다. 5-1절을 보세요 |

| 화면에 CORS 오류 | `WIMB_CORS_ALLOWED_ORIGINS` 주소가 실제 도메인과 다릅니다 |
| 모든 검색이 "확인 불가" | 인증키가 아직 활성화되지 않았을 수 있습니다. `docker logs wimb-api` 에서 `vitalizationErr` 를 찾아보세요 |
