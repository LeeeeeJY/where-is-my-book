# 도서관 주소 규칙 채우기 — 사람이 해야 하는 일

읽고 싶은 책을 찾았는데 링크를 누르면 **도서관 첫 화면**이 뜹니다. 거기서 다시 검색해야
하니, 이 도구가 없애려던 수고가 마지막에 그대로 남습니다.

이 문서는 그것을 없애기 위해 **직접 해 주셔야 하는 일**과, 왜 자동화할 수 없는지를 적어
둔 것입니다. 한 도서관당 3분이면 됩니다.

---

## 왜 손이 필요한가

**정보나루가 도서관 홈페이지 주소만 주기 때문입니다.** 매뉴얼 1절과 13절의 응답 명세를
확인했고, 그 책의 상세 페이지 주소를 주는 항목이 없습니다. (`bookDtlUrl` 이 있긴 한데
정보나루 자기 페이지입니다.)

그리고 도서관마다 검색 주소 규칙이 다릅니다. 1,619곳이 저마다 다른 시스템을 씁니다.

**규칙을 짐작해서 넣으면 안 됩니다.** 틀린 규칙을 넣으면 그 도서관은 **HTTP 200 을 주면서
결과만 0건**이 됩니다. 사용자에게는 「소장한다더니 그 책이 없네」로 보이고, 소장 정보 자체를
믿지 않게 됩니다. 링크가 깨지는 것보다 나쁩니다. **깨진 링크는 눈에 보이지만 이건 안
보입니다.**

크롤링으로 자동 발견하는 것도 권하지 않습니다. 주말을 통째로 쓰고 쓸 만한 결과가 나오지
않습니다.

**1,619곳을 다 채우려 하지 마세요.** 자주 가시는 곳 몇 군데면 충분하고, 나머지는 홈페이지로
가되 화면이 「도서관 홈페이지로 이동」이라고 정직하게 밝힙니다.

---

## 채워 주실 표

**한 줄이 도서관 한 곳입니다.** 자주 가시는 곳부터 채우시면 되고, 다 채우지 않아도 됩니다.
한 줄만 넣어도 그 도서관은 바로 책 페이지로 갑니다.

| ① 도서관 이름 | ② ISBN 검색 결과 주소 | ③ 책 상세 주소 | ④ 제목 검색 결과 주소 |
|---|---|---|---|
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |
|  |  |  |  |

**②③④ 가운데 하나만 있어도 됩니다.** 셋 다 채우면 가장 좋은 것을 골라 쓰고, 그 책의
ISBN 을 모를 때 아래 단계로 내려갑니다.

| 칸 | 무엇 | 얼마나 좋은가 |
|---|---|---|
| ③ | 검색 결과에서 책을 눌러 들어간 **그 책 화면**의 주소 | 가장 좋습니다. 검색을 한 번 더 거치지 않습니다 |
| ② | 검색창에 **ISBN 을 넣고** 검색한 결과 화면의 주소 | 결과가 한 건이라 사실상 상세와 같습니다 |
| ④ | 검색창에 **제목을 넣고** 검색한 결과 화면의 주소 | 동명이서가 섞입니다. ②가 0건일 때만 씁니다 |
| (없음) | 셋 다 못 채운 도서관 | 지금처럼 홈페이지로 가고, 화면이 그 사실을 밝힙니다 |

### 각 칸을 얻는 법

시험용 ISBN 은 `9788983711892`(코스모스 특별판)입니다. **그 도서관이 실제로 가진 책이어야**
결과가 나오므로, 안 나오면 그 도서관 소장 목록에서 아무 책이나 골라 쓰세요.

1. 그 도서관 홈페이지의 **자료검색**에 ISBN 을 그대로 넣고 검색합니다.
2. 결과가 나온 화면의 **주소창을 통째로 복사**해서 ②에 붙입니다.
3. 결과에서 책 제목을 눌러 들어간 화면의 주소도 복사해서 ③에 붙입니다.
   다만 그 주소에 **ISBN 이 보이지 않으면 ③은 비워 두세요.** 도서관 내부 등록번호는
   책마다 달라서 규칙으로 만들 수 없습니다.
4. ②가 0건이면 제목(`코스모스`)으로 검색해 ④를 채웁니다.

주소는 자르지 말고 **있는 그대로** 붙여 주세요. 뒤에 붙은 파라미터가 검색 조건일 때가
있어서, 지우면 결과가 달라집니다.

### 제가 하는 일 (안 하셔도 됩니다)

| 칸 | 어떻게 |
|---|---|
| 도서관부호 | 이름으로 `/api/libraries` 에서 찾습니다 |
| 종류 판정 | 주소 모양을 보고 `ISBN_DETAIL` / `ISBN_SEARCH` / `TITLE_SEARCH` 를 고릅니다 |
| 인코딩 | ④ 주소의 한글이 `%C4%DA...` 면 `EUC-KR`, `%EC%BD%94...` 면 `UTF-8` 입니다 |
| 자리표 | ISBN 자리를 `{isbn13}`, 제목 자리를 `{title}` 로 바꿉니다 |
| 넣기와 확인 | `templates.csv` 에 넣고, **다른 ISBN 으로 한 번 더** 열어 확인합니다 |

**주소를 복사하는 일만 사람이 할 수 있습니다.** 나머지는 제가 합니다.

### 한 곳을 확인하면 여러 곳이 함께 채워집니다

여러 도서관이 **같은 통합 OPAC** 을 씁니다. 실제 목록 1,619곳의 홈페이지 주소를 세어 보면
확인할 묶음은 864개이고, 큰 묶음 하나가 수십 곳을 덮습니다.

| 묶음 | 함께 채워지는 곳 |
|---|---|
| `phlib.pohang.go.kr` | 41곳 |
| `lib.gimhae.go.kr/01293` | 39곳 |
| `bcl.go.kr` (부천) | 34곳 |
| `nowonlib.kr` | 27곳 |
| `unilib.dobong.kr` | 27곳 |
| `library.daegu.go.kr/dalseolib` | 12곳 |

**다만 같은 호스트라도 경로가 다르면 다른 묶음입니다.** 대구는 `library.daegu.go.kr` 하나에
61곳이 모여 있지만 구마다 `/dalseolib`, `/junggu`, `/bukgs` 로 갈립니다. 검색 주소에
도서관을 지정하는 파라미터가 붙는 곳도 있어서, **묶음 안의 다른 도서관으로 한 번 더 열어
보고 나서** 함께 넣습니다. 그것도 제가 합니다.

그러니 자주 가시는 곳을 채우실 때, 그 도서관이 시립·구립 통합 시스템을 쓰면 옆 도서관까지
덤으로 붙습니다.

## 전부 채우려면 (`scripts/opac-discover.py`)

한 곳씩 손으로 채우는 것과 별개로, **묶음 전체를 돌며 규칙을 찾아 검증하는 도구**를 두었습니다.

```bash
./scripts/opac-discover.py --probe        # 검증용 소장 데이터 만들기 (우리 API 를 씁니다)
./scripts/opac-discover.py --limit 30     # 큰 묶음부터 30개. 먼저 이걸로 성공률을 재세요
./scripts/opac-discover.py --all          # 전부. 중단해도 이어서 됩니다
./scripts/opac-discover.py --emit >> backend/src/main/resources/opac/templates.csv
```

**이것은 「크롤링으로 규칙을 자동 발견하지 마세요」를 어기는 것이 아닙니다.** 금지된 것은
주소를 짐작해서 넣는 일이고, 이 도구가 하는 일은 **그 도서관이 자기 검색 폼으로 알려 준
주소**를 그대로 써 보고 **응답 본문에 그 책이 실제로 나오는지 확인**하는 것입니다.
확인을 통과하지 못하면 버립니다. 그래서 검증을 세 겹으로 겹칩니다.

| 단계 | 무엇을 넣나 | 무엇을 잡나 |
|---|---|---|
| 양성 | 그 도서관이 **실제로 소장한** 책의 ISBN | 규칙이 아예 안 통하는 곳 |
| 음성 | **존재하지 않는** ISBN | 검색어를 무시하고 늘 전체 목록을 뿌리는 곳 |
| 재확인 | 그 도서관이 소장한 **다른** 책 | 첫 번째만 우연히 맞은 곳 |

양성에 쓰는 ISBN 을 아무 책으로나 고르면 안 됩니다. **그 도서관이 그 책을 안 가졌을 때
0건이 나오는데, 규칙이 틀린 것인지 책이 없는 것인지 구별할 수 없습니다.** 그래서 `--probe`
가 정보나루에 먼저 물어 도서관마다 「확실히 소장한 책」을 만들어 둡니다. 실측으로 1,619곳
가운데 1,555곳(96%)에 검증용 책이 두 권 이상 잡혔습니다.

음성 대조가 없으면 **검색어를 무시하는 OPAC 이 전부 「성공」으로 통과합니다.** 그런 규칙을
넣으면 어느 책을 눌러도 남의 책 목록이 뜹니다.

판정이 실제로 그렇게 도는지는 `./scripts/test-opac-discover.py` 가 가짜 OPAC 일곱 종류를
띄워 확인합니다. 규칙을 **찾아내는 것보다 잘못된 것을 걸러 내는 것**이 중요해서, 일곱 중
셋은 「반드시 버려야 하는」 사례입니다.

외부 서버에 대한 예의는 지킵니다. 같은 호스트에 한 번에 하나씩 3초 간격이고(`--host-delay`),
서로 다른 호스트끼리만 겹치며(`--concurrency`), `robots.txt` 에서 거부한 경로는 건드리지
않습니다. 한 묶음이 그 서버에 보내는 요청은 열 번 안쪽입니다. **이 값을 올리기 전에
`CLAUDE.md` 의 「외부 서버에 대한 예의」를 읽으세요.**

**실제 성공률은 아직 재지 못했습니다.** 도구를 만든 환경에서 도서관 사이트로 나가는 접속이
막혀 있어서, 가짜 서버로 판정 로직만 확인했습니다. 네트워크가 열린 곳에서 `--limit 30` 으로
먼저 재 보세요. 성공률이 낮게 나오면 「자동 발견은 가성비가 없다」는 기존 판단이 여전히
맞는 것이고, 그때는 자주 가는 곳만 손으로 채우는 편이 낫습니다.

### 브라우저만 있을 때 (조사와 반영을 나누기)

스크립트를 돌릴 수 없는 자리에서도 조사할 수 있습니다. 브라우저를 쓸 수 있는 사람이나
웹의 클로드에게 **작업 목록**을 주고, 받은 결과를 여기서 CSV 로 바꿉니다.

```bash
./scripts/opac-discover.py --worklist 30 > 작업목록.md    # 조사할 묶음 30개를 표로
./scripts/opac-discover.py --import-file 결과.txt \
    >> backend/src/main/resources/opac/templates.csv      # 받은 결과를 CSV 로
```

작업 목록은 묶음마다 **그 도서관이 실제로 소장한 책**을 함께 적어 줍니다. 이것이 없으면
조사하는 쪽이 아무 ISBN 이나 넣게 되고, 0건이 나왔을 때 규칙이 틀린 것인지 그 책이 없는
것인지 구별할 수 없습니다.

받은 결과는 그대로 믿지 않고 거릅니다. 실행해 보지 않고도 잡을 수 있는 것들입니다.

| 거르는 것 | 왜 |
|---|---|
| 자리표(`{isbn13}`, `{title}`)가 없는 줄 | 어느 책을 눌러도 같은 페이지가 나옵니다 |
| **다른 기관 도메인으로 보내는 줄** | 열어 보지 않고 지어낸 주소가 가장 잘 걸리는 자국입니다 |
| 모르는 묶음·종류·인코딩 | 옮겨 적다 어긋난 것입니다 |
| 종류와 자리표가 어긋난 줄 | `TITLE_SEARCH` 인데 `{isbn13}` 을 쓴 경우 |

서브도메인이 다른 것은 통과시킵니다. 검색이 별도 호스트에 있는 도서관이 실제로 있어서,
호스트가 정확히 같은지가 아니라 **같은 기관인지**를 봅니다.

**다만 이 거르기로 「실제로 그 책이 나오는지」까지 확인되지는 않습니다.** 그 확인은 위의
`--limit`/`--all` 만 합니다. 그래서 조사하는 쪽에 **세 번 열어 보게** 시키고(소장한 책 →
다른 책 → 있을 수 없는 ISBN), 결과에 그 사실을 적게 합니다. 작업 목록이 그 절차를 함께
담고 있습니다.

## 도서관부호를 미리 아시려면

굳이 필요하진 않지만(이름만 주시면 제가 찾습니다), 직접 보시려면 이렇게 합니다.
「성남」 자리에 찾으시는 이름을 넣으세요.

```bash
curl -s https://where-is-my-book.duckdns.org/api/libraries | python3 -c "
import json,sys
for r in json.load(sys.stdin):
    if '성남' in r['name']:
        print(r['libCode'], r['name'], r['homepageUrl'])
"
```

로컬에서 서버를 띄우셨다면 `localhost:8080` 으로 바꾸면 됩니다. 맨 앞의 숫자가
도서관부호입니다.

## 넣는 형식

제가 아래 형식으로 바꿔 `backend/src/main/resources/opac/templates.csv` 에 넣습니다.

```
141053,ISBN_SEARCH,UTF-8,https://lib.example.kr/search/index?q={isbn13}&type=all
```

| 칸 | 내용 |
|---|---|
| 1 | 도서관부호 |
| 2 | `ISBN_DETAIL` \| `ISBN_SEARCH` \| `TITLE_SEARCH` |
| 3 | 인코딩. 보통 `UTF-8` |
| 4 | 주소. ISBN 자리를 `{isbn13}`, 제목 자리를 `{title}` 로 바꿉니다 |

**자리표가 없으면 서버가 뜨지 않습니다.** 자리표 없는 규칙은 어느 책을 눌러도 같은 페이지가
나오는데, 조용히 엉뚱한 곳으로 보내느니 뜰 때 실패하는 편이 낫기 때문입니다.

한 도서관에 여러 줄을 넣어도 됩니다. 좋은 것부터 고르고, 그 책의 ISBN 을 모를 때 다음
줄로 내려갑니다.


나온 주소를 브라우저에 붙여 그 책이 실제로 뜨는지 봅니다.

## 자주 걸리는 경우

**주소에 ISBN 이 안 보입니다.**
POST 로만 검색하는 OPAC 입니다. 이런 곳은 **규칙을 만들 수 없습니다.** 홈페이지 폴백으로
두시면 되고, 화면이 그 사실을 밝힙니다.

**ISBN 으로는 안 나오는데 제목으로는 나옵니다.**
`TITLE_SEARCH` 로 넣습니다. 다만 동명이서가 섞이므로 ISBN 검색보다 나쁩니다.
그리고 **한글 질의어라 인코딩을 확인해야 합니다.** 주소창의 한글이 `%C4%DA...` 처럼
보이면 `EUC-KR`, `%EC%BD%94...` 처럼 보이면 `UTF-8` 입니다. 틀리면 200 이 오면서 결과만
0건이 됩니다.

**상세 페이지 주소를 바로 알 수 있습니다.**
검색 결과에서 책을 눌러 들어간 주소에 ISBN 이 들어 있으면 `ISBN_DETAIL` 로 넣습니다.
검색 결과를 한 번 더 거치지 않아 가장 좋습니다. 다만 그 주소가 ISBN 이 아니라 도서관 내부
등록번호를 쓰면 안 됩니다. 책마다 달라서 규칙으로 만들 수 없습니다.

**주소창이 안 바뀌고 화면만 바뀝니다.**
검색 결과를 자바스크립트로 그리는 OPAC 입니다. 주소를 복사해도 검색어가 들어 있지 않으므로
규칙을 만들 수 없습니다. 홈페이지 폴백으로 둡니다.

홈페이지로 갑니다. 화면(`/api/libraries` 의 `linkKind`)도 1,619곳 전부가 `HOMEPAGE` 입니다.

한 줄이라도 넣으면 그 도서관만 바로 책 페이지로 갑니다. 나머지는 그대로 홈페이지로 가고,
화면은 어느 쪽인지 매번 밝힙니다. 그리고 **규칙이 있는 도서관에만 「이 책 페이지」 배지가
붙어 오히려 눈에 띕니다.** 드문 것에 표시를 다는 편이 흔한 것에 다는 편보다 잘 읽힙니다.

넣는 것 말고 고칠 코드는 없습니다. `/api/go/{libCode}` → `OpacTemplates.bestFor` →
화면 배지까지 이미 이어져 있고, CSV 만 기다리고 있습니다.
