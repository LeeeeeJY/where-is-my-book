# 0단계 사전 검증 체크리스트

계획의 전제를 실물로 확인하는 단계입니다. 여기서 나온 결과에 따라 1단계의 세부가 달라지므로 반드시 먼저 끝냅니다.

**인증키 승인 대기가 크리티컬 패스입니다.** 신청을 먼저 걸어 두고, 기다리는 동안 API가 필요 없는 작업을 병행하세요.

## A. 사람이 직접 해야 하는 일 (승인 대기 있음)

### A-1. 정보나루 인증키

1. [ ] https://www.data4library.kr 회원가입
2. [ ] **데이터 활용 > 인증키 이용신청**. 사용 목적과 용도를 적습니다.
   - 적을 내용: 개인이 사용하는 도서관 소장 정보 조회 도구, 비영리, 소장 여부만 표시하고 대출 상태는 사용하지 않음
3. [ ] 승인 대기
4. [ ] 승인 후 **마이페이지 > 인증키 관리**에서 서버 IP 등록
5. [ ] 1일 한도가 30,000건으로 표시되는지 확인

### A-2. 고정 IP

A-1의 4번보다 먼저 준비되어야 합니다. 등록할 주소가 있어야 등록을 할 수 있습니다.

1. [ ] Fly.io 앱 생성 후 전용 IPv4 할당 (`fly ips allocate-v4`, 월 약 2달러)
2. [ ] 할당된 주소를 A-1의 4번에 입력

**GitHub Actions에서 정보나루를 호출하면 안 됩니다.** 러너의 IP가 고정되지 않아 등록 효과를 받지 못하고 조용히 500건 한도가 적용됩니다.

### A-3. 국립중앙도서관 서지정보 인증키

1. [ ] https://www.nl.go.kr/NL/contents/N31101010000.do 에서 Open API 신청
2. [ ] `cert_key` 발급 확인

## B. 키가 나오면 실행

```bash
cp .env.example .env     # D4L_AUTH_KEY, SEOJI_CERT_KEY 를 채웁니다
./scripts/probe-apis.sh
```

`probe-out/REPORT.md` 가 아래 다섯 항목에 답합니다.

1. [ ] **`libSrchByBook` 의 `region` 이 필수인가** — 가장 중요합니다. 선택 항목이면 호출이 ISBN당 1회로 끝나고, 필수면 선택한 도서관이 걸친 시도 수만큼 곱해집니다.
2. [ ] `libSrchByBook` 응답이 도서관부호를 주는가, 정보나루 자체 코드를 주는가
3. [ ] `libSrchByBook` 과 `srchBooks` 의 평균 응답 시간 — 여러 권 확인의 지연이 여기서 결정됩니다
4. [ ] 서지정보 API 응답 필드 전체 목록 (표지 URL과 세트 ISBN 필드가 있는지 포함)
5. [ ] 정보나루 `libCode` 와 도서관부호의 관계

## C. 결과 반영

- [ ] 1번 판정을 `docs/구현계획.md` 1절의 "확인하지 못한 사항"에서 확인된 사실로 옮기기
- [ ] 1번 판정에 따라 3절의 호출량 추정 고치기
- [ ] 3번 측정값이 크면 자주 가는 도서관만 벌크로 미리 적재하는 경로(`holdings_mode`)를 앞당길지 판단
- [ ] 4번에 표지 URL이 있으면 "1차에는 표지 없이" 결정을 다시 볼지 판단
