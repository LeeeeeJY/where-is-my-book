# WIMB — Where Is My Book

전국 공공도서관 통합 검색 도구입니다. 자주 가는 도서관을 미리 골라 두면, 읽고 싶은 책이
그중 어디에 있는지 한 번의 검색으로 알려 줍니다. 상세 정보와 대출 신청은 해당 도서관
페이지로 넘깁니다.

읽고 싶은 책을 정해 두고도 도서관 홈페이지를 하나씩 열어서 따로 검색해야 하는 상황을
없애려고 만들었습니다. 한 번 방문해서 여러 권을 함께 빌리려 하면 확인할 것이 권수와
도서관 수를 곱한 만큼 늘어나기 때문에, 그 확인 과정이 사실상 매번 포기하게 되는 지점입니다.

---

## 이 도구가 하지 않는 것

두 가지는 의도적으로 하지 않습니다. 성능이나 구현 난이도 때문이 아니라 제품 결정입니다.

**대출 가능 여부를 표시하지 않습니다.** 제공되는 대출 상태 데이터는 조회일 전날 기준이라
실시간이 아닙니다. 부정확한 상태를 믿고 헛걸음하는 것이 이런 도구를 못 쓰게 만드는 가장 큰
요인이므로, 소장 여부까지만 보여 주고 대출 가능 여부는 도서관 페이지에서 확인하도록
넘깁니다.

**"미소장"과 "확인 불가"를 섞지 않습니다.** 소장 조회는 외부 호출이라 실패할 수 있는데,
그 실패를 미소장으로 표시하면 실제로 있는 책을 없다고 답하게 됩니다. 화면에서 두 상태는
문구도 배경색도 다르고, 확인하지 못한 책을 미소장 집계에 넣지 않습니다.

## 지금 어디까지 되는가

**정보나루에 실제로 요청을 보내 봤지만 아직 정상 데이터는 못 받았습니다.**
인증키가 활성화되지 않아(`vitalizationErr`) 오류 응답만 받은 상태입니다.
**정상 응답의 실제 모양은 여전히 확인하지 못했습니다.**

그 오류 응답 하나가 설계를 무너뜨릴 뻔한 것을 드러냈습니다. 정보나루는 **오류도 HTTP 200
으로** 돌려주는데, 그 본문에는 `lib` 도 `doc` 도 없습니다. 상태 코드만 보고 넘기면 빈 목록이
되고 화면은 그것을 **"미소장"으로 그립니다.** 실행해 보지 않으면 절대 드러나지 않는
종류였습니다.

무엇이 검증되었고 무엇이 아직 추측인지는 [`docs/가정과-검증상태.md`](docs/가정과-검증상태.md)
에 정리해 두었습니다. **API 응답을 본 적 없이 만든 부분이 있으므로 그것을 확인된 사실처럼
다루면 안 됩니다.**

| 영역 | 상태 |
|---|---|
| 도서관 선택 화면 (지역 계층, 이름 검색, 내 주변) | 실제 브라우저에서 동작 확인 |
| 세 상태 체크박스, URL 공유, 브라우저 저장 | 동작 확인 |
| 한 권 검색 화면과 네 가지 소장 상태 표시 | 응답을 흉내 낸 상태로 동작 확인 |
| **여러 권 동시 확인** (줄 해석, 도서관 순위, 한 곳에서 다 빌리기) | 응답을 흉내 낸 상태로 동작 확인 |
| 서지 정규화, 저작 묶기, 색인 생성과 검증 | 테스트 통과 (실제 서지로는 미검증) |
| DB 스키마와 색인 전환 | 실제 PostgreSQL 에 적용해 제약까지 확인 |
| 정보나루 호출부 | 실제 요청까지 확인. **정상 응답은 미확인** (키 미활성) |
| 오류 응답 처리 | 실제로 받은 본문으로 확인 (HTTP 200 오류, XML·JSON 양쪽) |
| API 서버 기동과 환경 변수 | jar 로 실제 기동해 확인 (키 검증, 예산·CORS 환경 변수) |
| 배포 설정 (Dockerfile, fly.toml) | 작성만 함. **이미지 빌드와 배포는 미확인** |
| 서지 적재 배치 | 아직 없음 (검색할 때마다 조회해서 그 자리에서 묶습니다) |
| 도서관 상세 페이지 링크 | 아직 없음 (홈페이지까지만 보냅니다) |

## 실행

### 준비물

**1차 범위에서는 정보나루 인증키 하나만 있으면 됩니다.** 매뉴얼을 확인한 결과 도서관
마스터(위경도 포함), 서지, 소장 도서관을 정보나루 하나가 모두 제공하기 때문에, 국립중앙도서관
서지정보 API 와 공공데이터포털은 나중에 서지 품질을 보강할 때 붙이면 됩니다.

```bash
cp .env.example .env
# .env 의 D4L_AUTH_KEY 를 채웁니다. 이 파일은 커밋하지 않습니다.
```

인증키 신청 절차는 [`docs/0단계-체크리스트.md`](docs/0단계-체크리스트.md) 에 있습니다.
**인증키를 받는 것과 서버 IP 를 등록하는 것은 한 묶음으로 처리해야 합니다.** 등록하지
않으면 1일 호출 한도가 30,000건이 아니라 500건으로 조용히 적용됩니다.

### API 서버

```bash
cd backend
set -a; . ../.env; set +a   # .env 를 환경 변수로 올립니다
./gradlew bootRun           # http://localhost:8080
```

`D4L_AUTH_KEY` 가 비어 있으면 서버가 그 사실을 말하고 뜨지 않습니다. 키 없이 조용히
떠서 모든 조회가 실패하는 것보다 낫기 때문입니다.

### 화면

```bash
cd frontend
npm install
npm run dev                # http://localhost:5173
```

API 서버가 없어도 화면은 뜹니다. 이때는 샘플 도서관 24곳으로 선택 화면만 동작하고,
**샘플이라는 사실을 화면 위쪽에 밝힙니다.** 책 검색은 서버가 있어야 합니다.

### 테스트

```bash
cd backend && ./gradlew test     # 정규화, 군집화, 색인, 어댑터, 정보나루 응답 파싱
cd frontend && npm test          # 선택 상태 계산과 URL 인코딩
./scripts/verify-schema.sh       # 마이그레이션과 스키마 제약 (루트가 아닌 계정으로)
```

## 구조

```
서지 → BibNormalizer → WorkMatcher → WorkClusterer → SearchDocBuilder → IndexVerifier
                                                                              ↓
검색어 → 저작 → isbn13_list 전체 → libSrchByBook (시도별) → 소장 도서관 → 고른 곳과 교집합
```

| 위치 | 내용 |
|---|---|
| `backend/src/main/java/kr/wimb/bib` | 정규화, ISBN 처리, 저자 대조, 판정 규칙(R0~R7), 군집화, `work_id` 승계 |
| `backend/src/main/java/kr/wimb/index` | 색인 문서 생성과 전환 전 검증 |
| `backend/src/main/java/kr/wimb/holdings` | 소장 조회. 미소장과 확인 불가를 타입에서부터 구분합니다 |
| `backend/src/main/java/kr/wimb/data4library` | **외부 API 형식을 아는 유일한 곳입니다** |
| `backend/src/main/java/kr/wimb/ingest` | 어댑터 계약, 호출 예산 원장, HTTP 재시도와 간격 제어 |
| `backend/src/main/java/kr/wimb/api` | Spring Boot 컨트롤러와 검색 서비스 |
| `backend/src/main/resources/db/migration` | PostgreSQL 스키마 |
| `backend/src/main/java/kr/wimb/query` | 붙여넣은 목록의 줄 해석. 외부 호출이 없습니다 |
| `frontend/src` | 도서관 선택, 한 권 검색, 여러 권 확인 화면 |

**서지는 미리 색인하고, 소장은 조회할 때 가져와 캐시에 쌓습니다.** 이 두 경로를 혼동하지
마세요. 서지 색인을 두는 이유는 호출량 절감이 아니라 검색 품질 통제이고, 한 저작에 묶인
ISBN 전체를 알아야 소장 조회가 정확해지기 때문입니다. 판본 하나만 조회하면 도서관이 다른
판을 가지고 있어도 미소장으로 나옵니다.

소장 데이터를 미리 적재하지 않는 이유는 1,604개관 벌크 적재가 1억 2천만 행에 이르는 데
비해, 조회 시점 호출이 호출 한도 안에서 충분히 감당되기 때문입니다.

### 여러 권 동시 확인

**이것이 이 도구를 실제로 쓰게 만드는 화면입니다.** 한 번 방문해서 여러 권을 빌리는 것이
실제 행동이고, 그 확인을 권수와 도서관 수를 곱한 만큼 반복하는 것이 이 도구를 만든 이유입니다.

두 단계로 나뉘어 있습니다.

1. `POST /api/check/resolve` 가 줄을 해석하고 책을 확정합니다. **줄 해석 자체에는 외부
   호출이 없으므로** 목록을 붙여넣은 직후에 화면이 그려집니다.
2. `POST /api/holdings` 를 책마다 따로 부르고, 답이 오는 대로 그 줄만 채웁니다.
   도서관 순위와 「한 곳에서 다 빌리기」는 도착할 때마다 다시 계산되며, 확인이 끝나지
   않았다는 사실을 함께 표시합니다.

캐시가 빈 상태로 30권을 확인하면 수십 초가 걸리는데, 그동안 빈 화면을 보여 주면 사용자는
이 도구를 다시 쓰지 않습니다. 그래서 이 순서를 지킵니다.

줄 해석 규칙(`kr.wimb.query.LineParser`)에서 알아 둘 것:

- 목록 번호는 **두 자리까지만** 뗍니다. 네 자리까지 허용하면 「1984. 조지 오웰」의
  「1984.」를 번호로 읽어 책을 통째로 잃습니다.
- 줄 전체를 제목으로 **먼저** 보고, 결과가 없을 때에만 제목과 저자로 나눕니다.
  순서를 뒤집으면 「82년생 김지영, 그 후」 같은 제목이 잘못 갈라집니다.
- 체크디지트가 틀린 숫자를 제목으로 넘기지 않습니다. 숫자 나열을 제목으로 찾으면 0건이
  나오는데, 사용자는 그것을 「이 책이 없다」로 읽습니다.
- 어떻게 읽었는지를 **항상 화면에 되돌려 보여 줍니다.** 사용자가 왜 이 결과가 나왔는지
  알아야 스스로 고칠 수 있습니다.

집계에서는 **확인하지 못한 책을 소장에도 미소장에도 넣지 않습니다.**
「고른 도서관에 없는 책」과 「확인하지 못한 책」은 화면에서도, 「결과 복사」의 글에서도
따로 적힙니다. 앞은 서점으로 넘어가야 하는 책이고 뒤는 다시 확인하면 있을 수 있는 책이라
행동이 다르기 때문입니다.

### 지금은 임시로 이렇게 되어 있습니다

`BookSearchService` 는 검색할 때마다 정보나루에서 서지를 받아 그 자리에서 묶습니다.
최종 설계는 서지를 미리 적재해 색인에서 검색하는 것인데, 그 적재를 아직 돌리지 않았습니다.
**정규화와 저작 묶기는 최종 설계와 완전히 같은 코드를 쓰므로**, 적재를 시작하면 이 클래스의
`fetchBooks` 만 색인 조회로 갈아 끼우면 됩니다.

도서관 링크도 지금은 홈페이지까지만 보냅니다. 도서관마다 OPAC 이 달라 상세 페이지 주소를
만들려면 벤더 계열별 템플릿이 필요한데, 그것은 실제 주소를 확인하며 채워야 합니다.
**어느 단계의 링크인지는 화면에 밝히고 있습니다.** 조용히 홈페이지로 보내면 사용자는
검색 결과 자체가 틀렸다고 생각하기 때문입니다.

## 배포

자세한 절차는 [`docs/배포.md`](docs/배포.md) 에 있습니다. 두 가지만 여기에 옮겨 둡니다.

**프론트만 Vercel 에 올리고 API 서버는 따로 둡니다.** Vercel 프로젝트의 Root Directory 를
`frontend` 로 지정하고, 환경 변수 `VITE_API_BASE` 에 API 서버 주소를 넣습니다.
API 서버는 `backend/Dockerfile` 과 `backend/fly.toml` 로 올리며, **배포 뒤 고정 IP 를
정보나루에 등록하는 것까지가 한 묶음입니다.**

**API 서버를 서버리스에 올리면 안 됩니다.** 정보나루에 등록할 고정 IP 가 API 서버에 붙어야
하는데, 서버리스는 나가는 IP 가 고정되지 않아 등록 효과를 받지 못합니다. 그러면 조용히 1일
500건 한도가 적용되고, 평소에는 멀쩡하다가 확인 두어 번에 한도가 소진되어 "확인 불가"가
쏟아지는 형태로 나타납니다. 같은 이유로 **GitHub Actions 에서 정보나루를 호출하지 않습니다.**

## 데이터 출처

출처: 도서관 정보나루 · 국립중앙도서관

화면에도 같은 문구를 표시합니다. 이용 조건상의 의무이면서, 소장 정보를 어디까지 믿을 수
있는지 알려 주는 표시이기도 합니다. 소장 정보에는 조회 시각을 항상 함께 표시합니다.
사용자가 "미소장"을 "확실히 없다"로 읽을지 "한 달 전 기준이다"로 읽을지가 그 표시 하나에
달려 있기 때문입니다.
